# 數位錯題本

## Proposal Report

### 動機與目標
我的微積分一直以來都不太好，考試和作業也常常錯誤百出，所以我希望能夠有更有系統、更方便查看自己曾經錯過的題目或考試壹定會考的經典題型的方法，不然每次都要一一去翻我之前做的筆記很麻煩也消磨我的動機。

### 預期功能
這個程式碼要有使用者介面(tkinter，也就是單機給我自己用)，且至少包含五個功能：

1.歸檔，讓我能夠依照單元分配資料夾來存放題目

2.上傳圖片的功能，如果原始題目是紙本，最好能夠直接拍照放上去，這樣方便很多。且有時候解答也會需要用照片形式儲存。

3.能夠讓使用者(我)自行撰寫解答的區域，可以圖文並茂幫助理解。

4.要有儲存的功能，不然如果每次我用完關掉app它就不見的話就完全失去錯題本的意義了。

5.能夠讓我在每個題目上標注本題難度(用小於2^32的數字)，而同個檔案夾裡面可以利用sorting將難度係數數由大到小/由小到大排序

6.(Optional)如果複習當下覺得解答寫的有點看不懂可以引入gemini AI現場解題，但這個功能我不確定能不能用手上的開發工具做出來，先保留。

### 競品比較

網路上我沒找到跟這個非常類似的軟體，但平板上的GoodNote和無邊記都可以充當錯題本。其實只要具有建檔、寫詳解的功能的軟體都算是廣義上的「錯題本」。而我的專案能夠脫穎而出的底方在於功能較為單一簡便，每一個欄位都已經幫使用者規劃好他們應該放什麼(如錯題、難度標記、單元標記等），且整個資料夾的架構也比GoodNote清楚易讀許多。

### 使用技術
使用文字編輯器sublime，且引進python的函式庫tkinter來完成使用者介面。
關於app關掉要如何儲存的問題，我會想辦法用上學期學的file input功能來完成。
我感覺自己一定會在某些環節卡住，所以會請Gemini來幫忙

### 遇到的困難
<!-- 遇到什麼問題、如何解決或打算如何解決 -->
一開始讓我卡關最久的就是上傳圖片的功能。不知道為何只要選擇上傳圖片，系統就馬上閃退。後來我問AI之後才知道這是平台相容性的問題---當程式呼叫 filedialog.askopenfilename 時，它會去呼叫 macOS 系統原生的「選擇檔案視窗」。這時候，Tkinter 試圖把我們設定的副檔名過濾器 filetypes=[("Image Files", "*.png;*.jpg;*.jpeg;*.bmp")] 丟給 macOS。在 Windows 系統中，用分號隔開副檔名是標準寫法；但在 macOS 中，底層的 Apple API無法解析這個分號字串，導致它在建立副檔名白名單的陣列時，產生了一個空值。而解決的方法是把 filetypes 的寫法，改成 macOS 和 Windows 都能看懂的Tuple格式。這是我原先完全沒想過的問題，但還好有AI幫我上了一課，不然不知道我自己偵錯的話還要debug多久。

目前程式碼沒遇到bug，但我也還沒用極端值(ex:打一個過大的難度數值)來確認程式的try-exception是否正確運行。而且感覺目前的功能還不夠完善，還沒有讓我真正開始使用這個app的動機。

## Final Report

### 專案說明

最終專案的成果與我上面計劃的差不多，預期的那六個功能除了Optional的以外皆有完成。
這是一個寫在電腦中的錯題本，讓使用者可以在寫題目的時候一看到不懂的問題，就馬上截圖並上傳到錯題本中，並手寫補上該題目的解答。雖然功能較爲陽春，沒有辦法讓AI幫助自動解題，但此專案在管理使用者錯題檔的方面相當具有系統性。我參考了Mac的Finder的資料結構，讓使用者可以自行建立資料夾儲存指定單元的錯題，也可以依照難度來分類錯題，讓使用者在考前複習瀏覽時可以快速找出指定單元的指定知識點來進行加強，這樣比去找四散的考卷和書本方便多了。

### 使用方式

使用起來十分直觀。我把每一個按鈕的功能都寫得清清楚楚，使用者只要點選“新建資料夾”，然後在裡面點選“新增錯題”並上傳圖片，就完成一題錯題的儲存了！而自行書寫的解答主要以文字形式呈現，但也可以和Google Docs一樣在中間插入圖片方便自己理解，同時也支援粗體、標色、放大等文字處理功能，讓筆記更加重點分明。但Google Docs絕對無法取代此錯題本，因為在檔案的瀏覽上，我的User Interface比Google Docs清楚多了，而圖片的上傳和解答的書寫都是專為此功能設計，相較於自己在Google Docs上雜亂地建檔來的方便快捷許多。

### 與課程的關聯總結

雖然我的專案沒有什麼花俏的功能或複雜的演算法，也沒有用到課堂上教的Tree或Hash Table等資料結構，但我覺得經過這堂課的洗禮，我會下意識地把一個一個錯題想成一個一個Node，而這個錯題本就是一顆大樹，開枝散葉長出了許多的節點，而每個節點都有對應的難度係數和知識點範圍(Properties)，那麼四捨五入也算是個Tree的實作了！

我覺得這個專案還有許多能夠新增的功能，像是我該如何應用剛剛提到每個Node的Properties，進行一些針對Tree的排序或其他功能上的實作。雖然我現在還想不到，可能是還沒有將上課的內容融會貫通，但我相信這個專案一定存在很多改進空間的。
